# 011 — Анонимная публикация

## Цель

Убрать trust-барьер: дать возможность опубликовать мультик **без регистрации**. Юзер нарисовал, понравилось, хочет поделиться — не заставляем заводить аккаунт. Снижает churn на финальном шаге воронки.

## UX flow

В publish-модалке (которая сейчас открывается по Save в Editor):

**Если юзер не залогинен:**
1. Модалка с заголовком «Publish your cartoon».
2. Поле `Display name` (обязательное, 2-32 символа) — как он подпишется под работой. Дефолт — «Anonymous».
3. Поле `Project name` + `Description` — как и сейчас.
4. Под кнопкой Publish — блок «💡 Create an account so you don't lose this cartoon and can edit it later» с кнопкой **«Sign up & keep this draft»**.
5. Две кнопки: `Publish anonymously` (серая), `Sign up first` (primary).nfr

**Если юзер залогинен:** всё как сейчас, без поля Display name и без CTA.

**Sign up & keep this draft**: сохраняет текущий draft в localStorage под ключом `post_signup_draft_id`, редиректит на `/register`. После успешной регистрации читаем этот ключ, переносим draft из анонимного dexie в юзерский (фактически — просто ассоциируем draftId с userId, если draft уже в dexie). Очищаем ключ. Возвращаемся в редактор с этим draft.

## Data model

### Project (расширение)

```js
{
  ...existing,
  owner: ObjectId | null,           // теперь nullable — для анонимных
  anonymousName: String,             // displayName из модалки при анонимной публикации
  anonymousFingerprint: String,      // hash(IP + userAgent) — для примитивной дедупликации и модерации
}
```

Индексы остаются. Убрать `required: true` на `owner`.

**Важно:** у анонимных проектов нельзя делать форк обратно в свой аккаунт (нет источника `User`). Когда залогиненный юзер форкает анонимный проект — всё штатно, новый draft привязывается к нему.

## API

```
POST /api/projects/publish               — существующий endpoint, теперь auth опционален
```

Валидации при анонимной публикации:
- `anonymousName` обязателен, 2-32 символа, trim, no HTML.
- **Rate limit**: 3 анонимных публикации в час с одного `anonymousFingerprint`. Жестче чем для залогиненных.
- Капча на третьей публикации в час — чтобы отсечь ботов. **Отложить**, если нет запроса.

Клиентская логика `publishProject`: если нет токена — не шлём `Authorization` header, добавляем поле `anonymousName` в multipart.

## Что анонимы НЕ могут

- Лайкать (лайк требует `userId` для unique constraint).
- Комментировать (в 006 — auth only).
- Иметь страницу профиля (нет username).
- Редактировать/удалять опубликованный мультик (нет owner → нет authZ).
- Форкать в «своё» (нужен юзер).

Что они могут: публиковать, смотреть, делиться ссылкой. Достаточно для первой публикации.

## UI детали

- На карточке в ленте и странице проекта — автор отображается как `Anonymous (Display Name)` или просто `Display Name`, без `@` и без клика на профиль (profile link скрыт).
- На странице проекта — baner сверху: «This cartoon was published anonymously» (opacity 0.6, мелкий).
- В `MyProjects` анонимные проекты не появляются (их нельзя привязать к юзеру после регистрации).

## Конверсия из анонима в юзера

Ключевое UX-решение: **после успешной публикации анонимно** — модалка «Your cartoon is live! Create an account to:
- Keep editing it later
- Get notified when people like it
- Join this week's challenge
[Sign up]»

Это второй touch-point после publish-модалки — ловим юзера на позитивной эмоции.

**Важно:** анонимный проект нельзя «усыновить» залогинившись позже (нет стабильной привязки IP/fingerprint недостаточно надёжна). Это known trade-off: если юзер зарегался после публикации, мультик остаётся анонимным навсегда.

## Открытые вопросы

- **Можно ли редактировать анонимно опубликованный мультик сразу после публикации** (в той же сессии)? Хранить `draftId → projectId` в localStorage, дать кнопку «Update» пока не закрыл вкладку? Минимальный жест лояльности. Подумать после MVP.
- **Display name — уникальный или нет?** Не уникальный. Два анонимных "John" могут существовать. Разрешать, это же display name.
- **Анонимная публикация + challenge** (005): можно ли участвовать в челленджах без аккаунта? Решение: **нет**. Участие в челлендже = ставится для учёта в топ-3 и выдачи бейджей, без юзера некому отдать badge. Если аноним — тегирование не применяется, хоть он и поставил галочку.
- **IP-based fingerprint** — считать на бэке по `req.ip` + user-agent. Хешировать чтобы не хранить IP напрямую (GDPR-friendly).
- **Если анонимная публикация становится вирусной** (много лайков) — показать это в виде «Anonymous cartoon has 1k likes» где-то? Или молча? Подумаем, если появится.
