# 009 — Локализация (EN/RU для старта)

## Стэк

`react-i18next` + `i18next-browser-languagedetector`. Стандарт де-факто, хорошая экосистема, поддерживает plural rules для RU.

## Структура

```
web/src/i18n/
  ├─ index.js            ← инициализация i18next
  └─ locales/
      ├─ en/common.json
      ├─ en/editor.json
      ├─ en/auth.json
      ├─ ru/common.json
      ├─ ru/editor.json
      └─ ru/auth.json
```

Namespace'ы: `common`, `editor`, `feed`, `auth`, `project`, `me`. Ленивая загрузка по namespace — не тащим весь словарь сразу.

## Миграция

- Текущий `web/src/configs/strings.js` уже содержит `getString(stringNames.xxx)` — маленький home-grown i18n. Заменить на `useTranslation()` + `t('...')`.
- Пройтись по компонентам, вынести hardcoded строки (в том числе мои ошибки `'Login failed'` и т.д.).

## Детектирование языка

1. localStorage `locale` — явный выбор пользователя (имеет высший приоритет).
2. `navigator.language` если ru-* → RU, иначе EN.
3. Fallback EN.

## UI

- В хедере или в `/settings` — селектор языка.
- Серверные ошибки **не локализуем в бэке** (сложно). Бэк возвращает коды `error_code`, клиент мапит в переводы. Переделать поля в API:
  ```json
  {"error": "email_already_in_use", "message": "Human readable fallback"}
  ```
  Либо оставить как есть, но клиент знает несколько ключевых строк и матчит по подстроке (хак, но работает для MVP).

## Плюрализация

RU имеет 3 формы: `1 мультик`, `2 мультика`, `5 мультиков`. `i18next` поддерживает через ICU plural rules из коробки.

```json
{
  "likes_count": "{{count}} like",
  "likes_count_plural": "{{count}} likes"
}
```
```json
{
  "likes_count_0": "{{count}} лайк",
  "likes_count_1": "{{count}} лайка",
  "likes_count_2": "{{count}} лайков"
}
```

## Даты

`date-fns` с локалями вместо `toLocaleDateString()`. Или `Intl.DateTimeFormat` — встроенный, плюс работает.

## User-generated content

**Не переводим.** Заголовки мультиков, комментарии, bio — как написаны. Это не баг, это фича: коммьюнити международное, люди сами знают что пишут.

## Объём работы

- 150-250 строк в коде, примерно 2-3 дня на полный перевод и вычистку.
- EN — "исходник", RU — переводим.
- Дальше добавление языков — просто новый JSON.

## Открытые вопросы

- Нужно ли добавлять UK, ES, PT, DE сразу? Нет, ждём реальный traffic из этих регионов. i18n-инфраструктура позволит за пару часов добавить новый язык.
- Перевод описаний челленджей (005) — автор админ задаёт на EN, нужен ручной перевод на RU? На MVP — только EN.
