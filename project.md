## Идея проекта (как запомнилось)

Простой онлайн-редактор мультиков в стиле «покадровой анимации» (flipbook):
- Пользователи рисуют короткие мультфильмы кадр-за-кадром.
- Есть тематические недели / челленджи — общая тема для всех.
- Работы публикуются в общую ленту.
- Есть система рейтинга/голосов, топы (`/hot`, `/new`, `/top`).

## Стек

**Backend** (`backend/`):
- Node.js + Express
- MongoDB + Mongoose
- JWT + Passport (Google/Facebook OAuth — каркас)
- Хранилище: Yandex Object Storage (S3-совместимое) через `tiny-storage-client`
- bcrypt, helmet, rate limiting

**Frontend** (`web/`):
- React 17 (CRA, `react-scripts`)
- Recoil — состояние редактора/таймлайна
- Konva.js — рисование на canvas
- MUI (`@mui/material`)
- React Router, dexie (IndexedDB), jszip
- `webp-animation-generator` — экспорт в WebP-анимацию
- `@dnd-kit` — drag-and-drop слоёв/кадров

## Критические проблемы

1. **Утечка ключей Yandex Cloud**: в `backend/src/routes/api/projects.js:17-22` захардкожены `accessKeyId` и `secretAccessKey`. Они уже в git-истории — их нужно ротировать в Yandex Cloud немедленно, до любой публикации репозитория.
2. **Логин-форма не рабочая**: пользователь не может залогиниться через email/пароль — только через Google (если серверный OAuth настроен).
3. **Feed.jsx — копипаста Login.jsx**: ленты как таковой нет, хотя в шапке есть ссылки на `/hot`, `/new`, `/top`.
4. **Экспорт не работает**: главная фича («сохранить мой мультик и поделиться») не доведена до конца — готового файла пользователь получить не может.
5. **Загрузки проектов нет**: сохранённый проект нельзя открыть обратно.
6. **Валидация входных данных отсутствует** (`projects.js:28` TODO).

## Что нужно доделать, чтобы «запустить MVP»

Минимум для запуска как редактора + ленты:
1. Ротировать утёкшие S3-ключи, вынести в `.env`.
2. Подключить форму логина к API (`signIn` в `modules/API/API.js`), сохранить JWT, добавить защищённые роуты.
3. Доделать экспорт в WebP (готовая либа уже в deps) + кнопка «Скачать».
4. Реализовать загрузку проекта по id (парсить zip из S3, восстанавливать слои/кадры).
5. Написать ленту: эндпоинт `GET /api/projects/feed?sort=hot|new|top`, UI с превью + плеером.
6. Базовая публикация (`published=true`, уже есть в модели) + отдельный список «мои проекты» в профиле.

Для полной исходной идеи (с челленджами и рейтингом) дополнительно:
7. Модель `Challenge` (тема + период + список работ) и крон на переключение темы.
8. Модель `Vote` (user, project, value) + агрегаты для сортировки `hot/top`.
9. Комментарии (`Comment`: project, author, text).
10. Email-рассылка (подтверждение регистрации + сброс пароля) — либо через SES/SendGrid, либо удалить подтверждение вообще на MVP.

Реалистичная оценка объёма: **4–8 недель** работы одного разработчика до жизнеспособного MVP, ещё столько же — до «приличного» состояния (модерация, репорты, мобильная адаптация, темы, теги, шаринг превью).

## Стоит ли доделывать? Есть ли смысл монетизировать?

### Аргументы «за»
- Ядро редактора (слои, кадры, onion skin, playback) уже работает — это нетривиальная часть, и она сделана.
- Ниша «сообщество для покадровой анимации с челленджами» действительно существует и пустовата в русскоязычном сегменте. Самые близкие конкуренты — **FlipAnim**, **Wick Editor**, **Piskel** (pixel-art), **Animatic** (iPad), **Procreate Dreams**. Из них «соц. сеть с челленджами вокруг мультиков» — это именно FlipAnim, и он старый, слабо развивается.
- Unit-экономика простая: хостинг ассетов в S3 дёшев, WebP компактны.

### Аргументы «против»
- **Рынок маленький**. Нишевые арт-сообщества монетизируются плохо: целевая аудитория — подростки и школьники, которые не платят за подписки. У FlipAnim за 10+ лет не получилось выйти за донаты.
- **Нет mobile-first**. Сейчас веб-редактор на десктопе, а реальная аудитория таких инструментов — планшеты/телефоны со стилусом. Konva на тач работает, но UI Editor-а под это не спроектирован.
- **Социальный слой с нуля**: лента, рейтинги, модерация, антиспам, жалобы — это ещё минимум месяц-два работы, и без этого коммьюнити не живёт.
- **Монетизация тонкая**: подписка за доп. слои/длительность/экспорт в HD, продажа кистей/пресетов, платные челленджи с призами, реклама — всё это начинает работать только при 10k+ MAU, до которых долго.
- Проект **заброшен** (по коммитам активность остановилась, «Add base backend» — последнее реальное движение).

### Рекомендация

Как коммерческий продукт — **слабо**: ниша узкая, аудитория неплатёжеспособная, путь до выручки длинный, конкуренты существуют и не смогли разогнаться сами. Для окупаемости одного разработчика нужна либо сильная дифференциация (AI-помощник для анимации, генерация in-betweens, шаблоны движений), либо другая аудитория (школы, курсы анимации — B2B SaaS).

Как **pet-проект / портфолио / открытый инструмент** — **да, имеет смысл**. Редактор уже наполовину готов, доделать его до работающего standalone-инструмента (без ленты, без аккаунтов, с локальным сохранением и экспортом) — 1–2 недели. Это даст:
- рабочий демонстрационный проект с Konva/Recoil/WebP-экспортом,
- возможный вариант «opensource FlipAnim-alternative» на GitHub,
- основу для экспериментов с AI-фичами (автоматический inbetweening — реально интересное направление в 2026).

**Конкретное предложение**: разделить на два шага.
1. **Шаг 1 (2 недели)**: доделать standalone-редактор. Починить undo/redo, экспорт в WebP + скачивание, локальное сохранение в IndexedDB (dexie уже в deps). Убрать бэкенд из критического пути. Это даст законченный полезный инструмент.
2. **Шаг 2 (опционально, +4–6 недель)**: если Шаг 1 соберёт пользователей — вернуть бэкенд, сделать ленту и челленджи. Если нет — оставить как есть.

Так минимизируются вложения, а решение о социальной части принимается по фактическому спросу, а не на вере.
